## חלק א — מפת ה-cluster

| רכיב | איפה הוא רץ (הנהלה / כל node) | מה הוא עושה, במשפט אחד | אנלוגיה |
|---|---|---|---|
| API server | הנהלה | נקודת הכניסה היחידה לאשכול: כל בקשה, מ-kubectl או מרכיב אחר, עוברת דרכו, והוא היחיד שמדבר עם etcd. | דלפק הקבלה: כל פנייה לבית החולים עוברת דרכו |
| etcd | הנהלה | מסד הנתונים ששומר את כל המצב של האשכול: אילו משאבים קיימים ומה ההגדרות שלהם. | ארכיון התיקים הרפואיים |
| scheduler | הנהלה | מחליט על איזה node ירוץ כל pod חדש, לפי המשאבים הפנויים והדרישות של ה-pod. | אחראי השיבוץ שמחליט באיזו מחלקה יאושפז כל מטופל |
| controller manager | הנהלה | בודק כל הזמן שהמצב בפועל תואם למצב הרצוי ומתקן פערים, למשל מקים pod חדש במקום אחד שנפל. | האחות הראשית שעוברת בסבבים ומוודאת שהכול כמו שצריך |
| kubelet | כל node | הסוכן שרץ על כל node, מקבל מההנהלה אילו pods צריכים לרוץ עליו, ודואג שהם באמת רצים ותקינים. | מנהל המחלקה שמקבל הוראות מההנהלה ודואג לביצוען במחלקה שלו |
| container runtime | כל node | התוכנה שמריצה בפועל את הקונטיינרים (אצלנו Docker), לפי ההוראות של ה-kubelet. | הצוות המטפל שעושה בפועל את העבודה בחדרים |
| kube-proxy | כל node | מנהל את כללי הרשת ב-node, כך שתעבורה שנשלחת ל-Service תגיע לאחד ה-pods שמאחוריו. | השילוט וההכוונה שמפנים כל מבקר לחדר הנכון |
| coredns | כל node (רץ כ-pod ב-kube-system) | שרת ה-DNS הפנימי של האשכול: מתרגם שמות של Services לכתובות IP, בדיוק כמו שב-Docker Compose (שיעור 4) קונטיינרים מצאו זה את זה לפי שם השירות. | המודיעין: "מחפשים את ד"ר כהן? שלוחה 34" |
